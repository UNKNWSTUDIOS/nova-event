act 1 why

Why leave a
site builder at all?

  • the builder was the right call in 2019
what the builder gives you
  • Speed for the first version.
  • A designer ships without an engineer.
  • Hosting, forms, CMS in one bill.
what it takes back
  • Seats. You pay per seat, per site, per collection. One rigid model, no flexibility.
  • Barriers. Every week there's a wall: this you can do, this you can't.
  • Page by page. One person, one page, one panel. Nothing runs in parallel.
  • The pipeline. Prototype → mockup → frontend → CMS → finish. That's not a 2026 process.
act 1 why

Rigid. Flexible.

  • what a page is, in each model
builder · rigid

Components live inside sections. Sections are concrete. A page is sections stacked. Want something the section doesn't allow? You don't.

code · flexible

Styles + rules, nothing pre-shaped. Every page is code written against the same tokens. Any layout, any motion — still on-brand, because the rules are the brand.

act 3 system

Now build it.

  • the brief after the audit — in this order, for these reasons

1 · framework. "Set up a Next.js app in TypeScript. Plain CSS."

2 · tokens. "From docs/inventory.md write globals.css :root: colour by role, a six-step type ladder, spacing, radius, motion. Round, don't copy."

3 · the rules. "Write design.md: never a raw value, reuse before building, every state change animates, never invent content."

4 · /ds. "Render every token on one page so a human can read the system."

5 · components. "Nav, footer, button, link, reveal. Nothing else yet."

6 · pages. "Now /about from the screenshots and the content file. Check it in the browser at 1440 and 390 before reporting."

colour · by role
--bg--bg-raised--ink--ink-muted--red--hairline
type · six steps
displayh1h2body-lgbodysmall
space · one scale
--pad-row--gap-cols--pad-x--pad-y--gap-section
shape · motion
--radius 12--ease-out · --dur 320

Why this order: tokens so nothing drifts · rules so corrections stick · components so change is cheap · pages last, because by then they're compositions.

act 4 running it

The economics.

  • a 10-page marketing site, off a builder
what it costs
2 weeks · 60–80 h of your time
  • One person who owns it, end to end.
  • Week one is the system: tokens, design.md, components. Week two is pages.
  • Tokens: tens of dollars. Hosting: free to ~$20/mo. Builder seats: gone.
  • After that, a page is an hour.
act 4 running it

What changes.

  • once the site is code on a system
01Anyone allowed builds pages.Marketing, product, a freelancer. Same tokens, same rules — it can't go off-brand.
02Time to market: hours, not weeks.A landing for tomorrow's campaign is built today.
03Iterations are fast and easy.No "let's discuss and approve" chain. Look at a preview link, say what's wrong, look again.
04The website becomes the source of truth.Decks, banners, campaign assets, proposals — generated off what's already there.

Five things.

01The builder is rigid: seats, barriers, page by page.Its pipeline was designed for 2019.
02Migrate in seven steps. Take content, leave code.Export, originals, URLs, screenshots, tokens, rebuild, DNS last.
03Tokens + design.md before any page.Designers write the rules; the pages get designed on top of them.
04One prompt, one page. For real.You saw the proposal. Reusable sections where you want them, freedom everywhere else.
