act 1 basics

Why leave a
site builder at all?

  • the builder was the right call in 2019
what the builder gives you
  • Speed for the first version.
  • A designer ships without an engineer.
  • Hosting, forms, CMS in one bill.
what it takes back
  • The ceiling. The interaction your competitor has is not in the panel.
  • The loop. Every change goes through a person clicking.
  • The system. Your brand has tokens; the builder has its own opinion.
  • The exit. Export is HTML soup or nothing. You rent your own site.
  • The bill. Per seat, per site, per CMS item — every year.

act 1 basics

Claude Code is an engineer
who lives in the terminal.

  • not a chat window
  • not a "generate my website" button
what it does
  • Reads the whole codebase.
  • Edits, runs, opens the browser, looks at the page.
  • Commits and deploys.
  • Follows written rules — yours.
what it isn't
  • A designer. Taste stays human.
  • Autonomous. Someone senior reviews.
  • Free — but cheaper than a seat.
what it needs from you
  • One person who owns the site end to end.
  • Rules written down.
  • Two weeks of patience, once.

The week changes.

  • this is the whole point
builder week
  • Design in Figma.
  • Rebuild it in the panel. Fight the panel.
  • Publish. Hope.
  • Marketing wants a change → ticket → panel → Friday.
  • Agency invoice for "site updates".
code week
  • Design in Figma, or straight in code.
  • Describe it. It's built against your tokens.
  • Look. Say what's wrong. Look again.
  • Push. Live in 40 seconds. Every branch a preview link.
  • Marketing wants a change → one sentence → same hour.
act 2 quirks

What you own
when you leave.

  • three builders, three different exits
Webflow
  • Static HTML/CSS export — pages only.
  • CMS as CSV.
  • Interactions: compiled, unusable.
  • The most honest exit of the three.
Framer
  • No code export.
  • CMS as CSV.
  • Components live only in Framer.
  • Motion is rebuilt by eye.
Wix
  • Nothing. Not even HTML.
  • CMS as CSV.
  • Velo code stays in Wix.
  • The live site is your only spec.
act 2 quirks

Take the content.
Leave the code.

  • the builder is a source of truth for content, never for code
take
  • Content — every collection, cleaned.
  • Assets — originals, not the CDN resizes.
  • URLs — every one, for the redirects.
  • Design decisions — read off the live site.
  • Screenshots — every page, desktop and mobile. That is the spec.
leave
  • Exported HTML as a starting point.
  • Animation code.
  • Structure, class names.
  • Forms, integrations, apps.
  • Rebuilding is faster than untangling. Every time.
act 2 quirks

Where migrations die.

  • each of these cost us a day, once
Webflow
  • Image quality. Export gives resized WebP; the originals live with whoever uploaded them.
  • Fonts. Not in the export. Licences need chasing.
  • Rich text arrives as HTML inside spreadsheet cells.
Framer
  • Scroll effects aren't CSS — they're rebuilt.
  • Breakpoints are per-frame; the new site needs real ones, decided first.
  • Localisation is a second project.
Wix
  • Pixel layout. Nothing maps to a grid; every page is redesigned, not ported.
  • Wix apps (forms, bookings) need replacements chosen before day one.
  • SEO. Ugly URLs, and every one needs a 301.

act 3 how we run it · system

Your taste,
written down.

  • one text file in the repo
  • read at the start of every session
rules · unknw.com (excerpt)

Design system first. Never a raw value in a component. A new hex means you skipped the token.

Re-use before building. Two components doing the same job is a bug.

Every state change animates. Nothing jumps.

Never invent clients, metrics or awards. Confirmed facts only.

Content lives in data, never in components.

  • Institutional memory. The "no, not like that" you said in March still holds in December.
  • Onboarding is reading a file. New designer, new agency, new model — same rules.
  • Quality is enforced, not requested. The rule is checked on every build.
  • Ours took a year of shipping to write. It's the most valuable file we own.

act 3 how we run it · pages

Briefing is the skill.

  • the model is only as good as the brief
  • this is a design skill, not an engineering one
what doesn't work

"Make it modern, minimal, premium, with smooth animations."

→ the same generic page everyone gets.

what works

Screenshots of the target. The content file. Which components to use. A tolerance. And: "check it in the browser before you report."

  • Pixels, not adjectives.
  • Evidence in, evidence out. It shows you the comparison.
  • Small steps. One page per session.
  • Same brief a good freelancer needs. That's not a coincidence.

act 4 what it takes

What we learned
the hard way.

  • a year of shipping, compressed
  • Screenshots beat Figma links. It can see them; it can compare against them.
  • Make it measure. "The nav looks off" → numbers first, then the fix.
  • Plan before build for anything bigger than a page. Read the plan. Then go.
  • Someone senior reviews. Always. It's a very fast junior.
  • Never let it invent. Copy, clients, numbers — real or nothing. Written as a rule.
  • Mobile is a second brief, not an afterthought.
  • Fonts are files and licences. Sort them on day one.
  • It will be wrong. Same fix as with people: clearer brief, smaller step.
