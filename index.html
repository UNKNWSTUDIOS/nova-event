act 2 quirks

Three builders,
three different exits.

  • what comes out, what doesn't
Webflow
exports
  • HTML / CSS / JS zip — static pages only.
  • CMS: CSV per collection.
  • Interactions: compiled Webflow JS, useless.
  • Classes are semantic-ish — the best starting point of the three.
Framer
exports
  • No code export.
  • CMS: CSV.
  • Components: only via Figma or by re-reading the live page.
  • Animations: rebuild — you get the motion values by looking, not by exporting.
Wix
exports
  • Nothing. Not even HTML.
  • CMS: CSV from collections.
  • Velo code is Wix-only.
  • Live DOM is div soup — treat it as a screenshot.
act 2 quirks

What you actually take.

  • the honest inventory
  • the builder is a source of truth for content, not for code
take
  • Content. CSV/JSON of every collection. Claude cleans it.
  • Assets. Images, videos, fonts — download originals, not the CDN resizes.
  • URLs. Every path; you will need redirects for the ones you change.
  • Design decisions. Type scale, spacing, colours — read them off the live site.
  • Screenshots. Every page, desktop + mobile, full length. This is your spec.
leave
  • Exported HTML as a starting point.
  • Interaction / animation code.
  • Class names, div structure.
  • Forms logic, integrations.
  • Rebuild those. It's faster than untangling.
act 2 quirks

The traps.

  • each cost us a day at least once
Webflow
  • Image CDN. Export gives 1600px WebP. Ask the client for originals or pull from the asset panel.
  • Rich text. CMS rich text comes as HTML in a CSV cell. Claude converts to MDX/JSON.
  • Fonts. Adobe/Google fonts aren't in the export. Get the licence files.
  • Symbols map 1:1 to React components — good.
Framer
  • Fake scroll. Framer's scroll effects don't live in CSS — rebuild with GSAP or motion.
  • Breakpoints are per-frame, not per-token. Decide your breakpoints first.
  • Text is often outlined in components. Check every headline is real text.
  • Localisation is a whole rebuild, plan for it.
Wix
  • Absolute positioning. Wix lays out by pixels. The new site must be a real grid; nothing maps.
  • Forms & bookings are Wix apps — pick replacements (Tally, Cal.com, Resend) before you start.
  • SEO. Wix URLs are ugly; the migration is your chance, but 301 everything.
  • Domain lock — DNS moves last.

act 3 pipeline · 2 system

Tokens first.
Always.

  • the one rule that makes everything else cheap
  • a raw hex in a component is a bug
globals.css · :root

--bg: #1e1e20; --bg-raised: #27272a;
--ink: #f4f4f2; --ink-muted: rgba(244,244,242,.64);
--red: #ff2e1a; --hairline: rgba(244,244,242,.14);

--font-display: var(--font-grafier);
--font-body: var(--font-unica);

--text-display: clamp(52px, 9.2vw, 164px);
--text-h1: clamp(40px, 6.4vw, 112px);
--text-h2: clamp(30px, 4vw, 64px);

--pad-x, --pad-y, --gap-section, --gap-cols
--radius, --shadow-card, --ease-out, --dur

  • Read them off the builder site. Claude opens the live page, reads computed styles, proposes a ladder. You edit the ladder.
  • Round to a system. The builder had 14 font sizes. You want 6.
  • Name by role, not value. --ink-muted, never --grey-64.
  • Put them on a page. /ds — palette, type, spacing, motion, patterns. Claude reads it before building anything.
  • Write the rule down. CLAUDE.md: "never a raw hex, never a bare font-size". It obeys.

act 3 pipeline · 2 system

CLAUDE.md is your
design director.

  • a text file in the repo root
  • read at the start of every session
CLAUDE.md · unknw-web (excerpt)

Design system first — tokens, never hardcoded values. Colour via --bg, --ink, --red… Never a raw hex in a component; a new hex means you skipped the token.

Re-use elements before building new ones. Look in components/ui/, components/fx/ first. Two components doing the same job is a bug.

Every state change animates. Nothing ever jumps statically.

Feed content lives in JSON. Never hardcode content in components.

Bump the build number on every ship.

  • Standing rules, not a to-do list. Things that must be true forever.
  • Written in your voice. Rules you'd tell a new hire on day one.
  • Grows with every correction. You said "no, not like that" → it becomes a rule.
  • Where the taste goes. The model has none of yours until you write it down.
  • Ours is ~150 lines. It took a year of shipping.

Things I wish
someone told me.

  • a year of shipping, compressed
  • Screenshots are the spec. Better than Figma links. It can see them.
  • Give it the browser. Playwright or the built-in tool. "Compare to the shot" beats "make it nice".
  • Make it measure. "The nav is weird" → ask for the numbers first, then fix.
  • Plan mode for big things. Ask for a plan, read it, then say go.
  • Skills / rules files for repeat work: "port a case study", "add a client logo".
  • Don't let it invent. Copy, clients, metrics — real or nothing. Write it as a rule.
  • Fonts are files. Put woff2 in the repo, licence them properly.
  • Mobile is a second brief, not a media query afterthought.
  • Cost. A site migration burned ~$60 of tokens for us. Cheaper than one Webflow month.
  • It will be wrong. Same as a junior. Same fix: clearer brief, smaller step.
